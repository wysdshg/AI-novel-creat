# 架构设计：上下文引擎 · 记忆层 · 去 AI 味 · SKILL 调度 · 接线

> 本文档说明「AI 小说创作智能体」在 2026-08-08 这一轮落地的五大基础模块：
> 上下文引擎、记忆层、去 AI 味、SKILL 调度，以及它们如何被「接线」到生成/商讨/前端。
> 对应 6 项原始需求：①AI 读写数据库 ②借鉴参考资料 ③依据上下文生成章节
> ④章后走向建议 ⑤去 AI 味 ⑥知道该调什么 SKILL。
> 配套上手文档：`README.md`、`API接口规范.md`、`PROJECT_REQUIREMENTS.md`。

```
            ┌───────────────── 上下文引擎（builder）─────────────────┐
            │  layers(取数) → budget(裁剪) → 拼 messages + SKILL + 去AI味 │
            └───────────────────────┬────────────────────────────────┘
                                     │ messages

## 2. 上下文引擎（需求 ③）

**为什么需要它**：写到第 80 章时，全量角色卡 + 设定 + 伏笔 + 历史记忆轻松突破十万字符，
任何模型都装不下。硬塞的结果是模型截断，且截掉的往往是排在最后的、最重要的「本章要点」。
所以必须先按重要性排定去留、再拼接。

### 2.1 三层装配

```
layers.py   取数：逐层把角色/设定/伏笔/记忆/商讨/参考 变成 Block
budget.py   裁剪：按 priority 分配字符预算，required 块永不丢
builder.py  装配：把各层 Block + SKILL 块 + 去AI味块 → 最终 messages
```

- **layers**：`layer_world / layer_characters / layer_entities / layer_foreshadows /
  layer_stage_summaries / layer_recent_memories / layer_prev_chapter / layer_discussion`。
  每个返回一个 `Block(key, title, content, priority, order, min_chars, required)`。
- **budget**：`plan_budget(blocks, level)` 按优先级降序装入；装不下且 `min_chars>0` 就截断，
  连最小值都不够则整块丢弃。全程留痕 `debug()`（前端「本次读取」面板的数据源）。
- **builder**：章节生成出口 `build_chapter_messages()` 与商讨出口 `build_discussion_system()`。
  关键设计——**「本章任务」放在 user 消息最后**（`required=True`，永不裁剪），因为小模型
  对末尾指令的遵循度明显高于夹在中间的指令。

### 2.2 预算口径（字符而非 token）

中文约 `1 token ≈ 1.5 字符`，但各家分词器不同。统一用**字符**做预算单位
——口径稳定、可解释、零依赖。三档：

| level | 字符 | 用途 |
| --- | --- | --- |
| `tight` | 8_000 | 本地小模型 / 追求速度 |
| `standard` | 32_000 | 默认（约 20K token 的安全线） |
| `loose` | 120_000 | 云端长窗口模型 |

`level` 可由配置 `KEY_CONTEXT_BUDGET` 覆盖，或调用方传 `budget_level`。
商讨预算比生成低一档（`loose → standard`），因为它吃不下那么多也没必要。

### 2.3 builder 出口结构

```
system = BASE_SYSTEM
       + skill_dispatch.build_block("chapter")   # SKILL 合集
       + humanizer.build_prompt_block(...)       # 去AI味硬约束
user   = budget.render()                          # 各层 Block 拼接（本章任务压尾）
```

返回的 `meta` 含 `budget.debug()`、`references` 命中明细、`mentions`、`skills.explain()`、
字符数——**全部通过 SSE `context` 事件推给前端**，让作者能看见「AI 这次到底读了什么」。

## 3. 记忆层（需求 ①④）

**为什么写后摄取，而非生成时同步**：生成已是流式长任务，再串一次抽取会让作者干等。
所以摄取放在正文落库**之后**单独跑，失败只影响记忆、不影响正文。

### 3.1 双表结构（`app/models/orm.py`）

- **章级记忆 `chapter_memories`**：每章一条，`upsert_chapter_memory` 按 `chapter_id`
  **覆盖写**（重生成不会产生两个版本）。含 `summary / ending_hook / characters /
  locations / plot_points / foreshadow_actions / new_entities / next_directions / status`。
- **阶段摘要 `stage_summaries`**：每 N 章（默认 10，`KEY_STAGE_EVERY`）把章级记忆压缩成
  一条阶段脉络。由 `find_uncompressed_range` 自动找出「下一个该压的区间」。

### 3.2 写后摄取主流程 `ingest_chapter()`

```
1. 抽取(extracted)     模型按「填空题式」JSON 指令抽取 → parse_json_loose 容错
                       失败 → fallback_extract（首尾段拼摘要 + 已登记实体子串匹配）
2. 落库                 upsert_chapter_memory（有新实体→status=pending，否则 confirmed）
3. 篇章摘要            append_article_digest（按 <!-- ch:N --> 标记追加，重生成只替换单段）
4. 走向卡片            discussion_crud.add_message(meta.type=post_chapter_directions)
5. 阶段压缩            find_uncompressed_range 够章数 → compress_stage
```

**每步独立 try，前步失败不阻断后步**——记忆抽歪了不该导致摘要也不写。

### 3.3 JSON 容错与规则兜底

本地 4B 输出 JSON 的成功率约八成。容错链（`parse_json_loose`）逐层救：
去 ```` ```json ```` 围栏 → 取首 `{` 尾 `}` → 三次尝试（原样 / 去尾逗号 / 全角引号转半角）。
仍失败则 `normalize_extract` 把模型可能给歪的结构掰回标准形状，
实在不行 `fallback_extract` 规则兜底，**保证记忆链不断**（下一章读得到前情）。

### 3.4 人类交接口（新实体确认）

小模型抽「新实体」容易抽错（如误把「青铜境」当新门派）。所以新实体先 `status=pending`，
**不自动入库**；前端 `GET /memory/pending-entities` 列出，作者点确认后
`POST /.../confirm-entities` 才按 `kind` 落到 `character/faction/location` 表（重名跳过）。
这条人工回路避免了「抽错境界 → 后续全崩」的连锁灾难。

## 4. 去 AI 味（需求 ⑤）

两条互不依赖的链路，刻意**不做「模型二次改写」**——本地 4B 二改会丢细节、把生动句子改平，
风险远大于收益。

### 4.1 前置注入（生成时）

`humanizer.build_prompt_block(scene, level)` 把最毒的几类规则塞进系统提示词。
刻意做得短——4B 对超长规则清单的遵循率断崖下跌。三档：

- `light`：只给最毒的 4 条（`tight` 档 / 小模型用，`h_level` 在 builder 里按此映射）
- `normal`：毒句式 + 写法准则（默认）
- `strict`：再加 OOC 防护与替换对照表（云端强模型用）

### 4.2 后置检测（写完后）

`humanizer.scan(text, scene)` **纯正则、零 token、不改写正文**。输出：
`score / grade / issue_count / per_thousand / issues[]`。
每个 issue 含 `rule_id / name / category / severity / matched / context / advice`。
改不改由作者决定（前端「AI 味检测」面板展示明细与修改建议）。

受配置 `KEY_HUMANIZE_SCAN` 开关控制；未配置可用模型时跳过。

## 5. SKILL 调度（需求 ⑥）

**旧做法的硬伤**：把所有 enabled 的 SKILL 字典序全拼进去——只有 discussion 场景有读取方，
且两个文风类 SKILL 同时开启会互相打架，模型只能随机二选一。

### 5.1 互斥 vs 叠加

- **互斥类**（文风 / 结构 / 视角 / 口吻）：同类只留 `priority` 最高的一个。
- **叠加类**（通用 / 禁忌）：全部保留——约束越多越好，不存在冲突。
- 拼接按 `priority` **升序**，高优先级压轴（模型对末尾指令更敏感）。
- 被互斥掉的 SKILL 在 `explain()` 的 `suppressed[]` 单独列出，前端提示作者「X 没生效，
  因为同为文风类的 Y 优先级更高」。

### 5.2 预置与幂等

`seed_skills.install(db)` 在 `main.py` 的 startup 事件里幂等安装 6 条预置 SKILL
（按 name 判重，已存在则跳过，不覆盖作者修改）：去AI味·网文正文(300) / 设定守卫(290) /
节奏引擎(200) / 白描文风(150) / 商讨顾问(100) / 记忆抽取规范(100)。
优先级即「压轴顺序」，去AI味排最后、最贴近指令末尾。

## 6. 接线全貌

### 6.1 路由装配

| 路由文件 | 职责 |
| --- | --- |
| `routers/chapter.py` | 生成走 `build_chapter_messages` + 写后摄取 + AI 味检测 + context 元信息 SSE |
| `routers/discussion.py` | `build_discussion_system` 注入全套设定，从「瞎子」变有依据的顾问 |
| `routers/memory.py` | 桩换真：摄取重跑 / 查章级记忆 / 阶段摘要 / 大事记 / 待确认实体 |
| `routers/assist.py` | AI 辅助总入口：去AI味检测/SKILL调度/配置/实体确认/资料推荐 |

### 6.2 章节生成 SSE 事件序列

```
start → context(读了哪些资料/块) → chunk* → validate(AI味报告)
     → saved(章节落库) → ingest_start → ingest(记忆/走向/阶段压缩结果) → done
```

### 6.3 前端最小改动（三处）

1. **走向卡片**：`ChatPanel.vue` 识别 `meta.type==post_chapter_directions` 渲染可点击选项卡；
   `ChatView.vue` 接 `pick-direction`，点选即把该走向发回商讨。
2. **上下文透明化 + AI 味面板**：`GenerateChapterDialog.vue` 消费 `context`/`validate`/`ingest`
   事件，展示「本次读取」「AI味评分+明细」「摄取进度」。
3. **API 封装**：`api/assist.js`（scan/humanizePrompt/dispatch/seedSkills/config/recommend）
   + `store/project.js` 透传 `meta`。

> 注：前端 `vite.config.js` 设 `emptyOutDir:false`——本沙箱把 `rmSync` 劫持成不稳定的
> 「安全删除」二进制，会导致 Vite 清空 dist 那步必崩；关闭后构建可正常完成。

### 6.4 实体确认人工回路（前端 → 后端）

```
前端 GET /memory/pending-entities
  → 作者勾选确认
  → POST /projects/{pid}/memory/confirm-entities  { entities:[{kind,name,brief}] }
  → 按 kind 调 character/faction/location_crud.create_*（重名跳过）
  → memory_crud.set_status(confirmed)
```

## 7. 关键契约（前后端字段对齐）

| SSE 事件 | 后端来源 | 前端消费字段 | 备注 |
| --- | --- | --- | --- |
| `context` | `builder.meta` | `budget.{kept,dropped,usage_pct}`、`references[].filename`、`skills.{active[].name, suppressed[].{name,reason}}`、`total_chars` | 透明化面板 |
| `validate` | `humanizer.scan` | `score/grade/issue_count/per_thousand`、`issues[].{category,matched,context,advice}` | 注意是 `advice` 非 `suggest` |
| `ingest` | `ingestion.ingest_chapter` | `memory_id/directions_pushed/new_entities/stage_compressed/fallback/error` | 写后摄取结果 |
