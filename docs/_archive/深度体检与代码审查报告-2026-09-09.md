## 3. 对照行业 Agent 落地全流程的短板

标准链路共 12 环，逐项对照：

| 环节 | 行业做法 | 本项目 | 评级 |
|---|---|---|---|
| 1 需求建模 | 能力边界与成功指标先行 | `PROJECT_REQUIREMENTS.md` 11 项需求清晰，但**无验收指标** | 🟡 |
| 2 知识 / RAG | 向量召回 + rerank + chunk 策略 | **无向量**（`reference_crud.py:483` 注释承认"本地无 embedding 模型"）；用目录 + 2-gram 关键词 + `LOAD_REFS` 按需加载。**取舍合理，但召回质量天花板低** | 🟡 |
| 3 工具调用 | schema 化 function calling + 重试 + 并行 | `LOAD_REFS:` / `LOAD_SETTING:` 是**自研行内文本协议**——有"按需取数"的正确意识，但靠模型自觉输出文本行，**无 schema 校验、无重试、无并行、模型不输出就静默失效** | 🟡 |
| 4 编排 | DAG 工作流 + 状态机 | ✅ `workflow_engine` 真跑（32 次节点执行），但只有 3 个工作流且与主链路双轨 | 🟢 |
| 5 记忆 | 分层记忆 + 压缩 + 检索 | ✅ **本项目最强项**：章级记忆 + 阶段摘要 + 大事记 + pending-entities + 上下文预算裁剪（`core/context/` 三件套） | 🟢 |
| 6 生成 | 流式 + 上下文预算 | ✅ SSE 流式 + `budget.py` 裁剪 + 思考链分离渲染 | 🟢 |
| 7 **评估 eval** | golden set + 自动打分 + A/B | ❌ **完全缺失**。`humanizer.py`（423行）只是**正则禁用词表扫描**，是"事后检查"不是"评估"。无基准集、无 A/B、无人评回收 | 🔴 |
| 8 **观测** | trace 串联 + token/成本 + 失败归因 | ⚠️ 有埋点（`discussion_load_logs`、`workflow_node_runs`），但**无 UI 消费端**；`trace_id` 生成后无处可查；**无 token 计数、无成本统计** | 🔴 |
| 9 **反馈闭环** | 采纳/拒绝信号回流，驱动迭代 | ❌ 无。用户改了章节、拒了走向、删了角色，**模型下次照样犯同样的错** | 🔴 |
| 10 安全护栏 | 内容过滤 + prompt injection 防护 | ❌ 参考文档正文直接拼进 prompt，无注入防护；无内容安全过滤 | 🔴 |
| 11 **工程基建** | 测试 + CI + 结构化日志 + DB 迁移 | ❌ **零测试、零 CI、零 logging**；DB 迁移靠 `init_db` 自动 `ALTER TABLE ADD COLUMN`（只能加列，改列/回滚做不到） | 🔴 |
| 12 成本/延迟治理 | 预算上限 + 降级熔断 + 缓存 | ❌ 无 token 计量、无预算上限、无失败降级 | 🔴 |

**结论：功能层（4/5/6）达到可用水平，但"让 agent 持续变好"的闭环（7 评估 / 8 观测 / 9 反馈）三环全断。**
这是"能用"和"能落地"的分水岭——没有 eval 与反馈，加再多功能也不知道是变好了还是变坏了。

## 5. 客观评级

# 评级：入门

（五档：完全不能用 / 非常差 / 差 / **入门** / 勉强能用）

### 评级依据

**为什么不是"勉强能用"（差一档）**

1. **11 项核心需求只落地 6 项**，且 4 项是纯空壳（`directions`/`outlines`/`foreshadows`/`skills` 数据库 0 行，不是"少数据"是"从没写过"）。
2. **agent 闭环三环全断**——评估、观测消费、反馈回收。一个不知道自己好不好、也不知道用户在不在用它的系统，按行业定义只能算"原型"，不算"可落地"。
3. **工程底座为零**：零测试、零 CI、零 logging。git 16 提交 11 次是 fix，说明每次改动都在赌。这直接决定了它不可交付给第二个人维护。
4. **存在会污染数据的 bug**：错误文案落库成正文、级联删除留孤儿、假绿灯校验。这些不是"体验问题"，是"数据可信度问题"。

**为什么不是"差"（高两档）**

1. **主链路被真实跑通过**，不是 demo：DB 里 8 章、33 条章记忆、31 条对话、32 次工作流节点执行。
2. **架构分层是对的**：router / service / core(gateway+context+workflow_engine) 边界清晰，新增厂商只需继承 `BaseModelAdapter`，新增模块只需加 meta——扩展性设计经得起检验。
3. **有几块是真资产**：`core/context/` 上下文引擎（budget/layers/builder）、记忆层（章级+阶段+大事记+待确认实体）、SKILL 调度、真实多厂商网关。**记忆与上下文这一块，比很多同类玩具项目做得认真。**
4. **按需加载协议（`LOAD_REFS`/`LOAD_SETTING`）方向正确**——在只有 chat 模型没有 embedding 的前提下，用"目录常驻 + 模型主动点菜"解决窗口爆炸，是个聪明的取舍。
