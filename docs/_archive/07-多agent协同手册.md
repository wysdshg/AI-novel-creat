# 07 · 多 agent 协同工作手册

> 最后更新：2026-09-09  
> 适用：调度 WorkBuddy（专用上下文）+ 4 个执行 agent（WorkBuddy 写码 / TRAE / Zcode / OpenCode）

## 1. 架构

```
                    ┌──────────────────────────┐
                    │  调度 WorkBuddy（专用对话） │
                    │  - 听需求 → 拆任务              │
                    │  - 生成「任务卡」文件            │
                    │  - 验收产出 + 检查冲突            │
                    └──────────┬───────────────┘
                               │ 任务卡 + 上下文快照
                ┌─────────┬─────┴─────┬─────────┐
                ▼         ▼           ▼         ▼
          ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
          │ WB 写码  │ │  TRAE  │ │ Zcode  │ │OpenCode│
          │ (主)    │ │        │ │周末专用 │ │轻量任务 │
          └────┬───┘ └───┬────┘ └───┬────┘ └───┬────┘
               │         │          │          │
               └─────────┴──────────┴──────────┘
                             │
                    ┌────────▼─────────┐
                    │  docs/06 + CHANGELOG   │  ← 共享真相
                    │  (每个 AI 接手必读)       │
                    └────────┬─────────┘
                             │
                    ┌────────▼─────────┐
                    │  E:\AI小说创作      │
                    └──────────────────┘
```

**关键不变量**：
- 调度 WB **不写代码**、**不调用其他 AI**、**不打开 IDE**——纯分诊 + 出任务卡 + 验收
- 每个执行 agent **必读** `docs/06-AI工作手册.md` + 当天 `CHANGELOG.md` 才能动手
- 所有改动记入 `CHANGELOG.md`，下个 agent 接手前先 diff CHANGELOG 看变化

## 2. 角色定位（按模型能力分）

| Agent | 主用模型 | 适合任务 | 不适合任务 |
|---|---|---|---|
| **WorkBuddy（写码）** | GLM-5.3-flash / deepseek-v4-flash / 混元4 | 架构设计、跨模块重构、调试 bug、写后端、改 prompt、解流式问题 | 纯文档编辑、跑小脚本 |
| **TRAE** | deepseek-v4-flash | 改前端、写单元测试、补类型定义、生成测试数据 | 复杂推理、跨模块协调、架构决策 |
| **Zcode（周末专用）** | GLM-5.3-flash | **集中攻坚**：Phase 0~2 中有难度模块、长上下文任务、复杂 bug 排查 | 日常小活（性价比低） |
| **OpenCode** | Ling / Muse / Nemotron / MiMo / Big Pickle（免费轻量） | **仅限轻量微任务**：单文件改写、写注释、补测试用例、改 README、处理日志、生成 fixture | 架构、调试、长上下文、长生成 |

**核心规则**：模型能力差 3 倍以上就别让它们协作同一段代码。强模型写骨架，弱模型填血肉。

## 3. 调度 WorkBuddy 的工作流程

### 3.1 接任务

用户提需求 → 调度 WB：

1. 读 `docs/01`（目标）、`docs/02`（当前实现）、`docs/03`（规划）确认任务在范围内
2. 拆分为 1-N 个子任务，每个子任务匹配一个 agent
3. 为每个子任务生成**任务卡**（见 §4）
4. 把所有任务卡写到 `E:\AI小说创作\.workbuddy\tasks\YYYY-MM-DD-<task-name>.md`
5. 提示用户：哪个任务卡发给哪个 AI

### 3.2 验收产出

用户说"X 已完成" → 调度 WB：

1. 读 CHANGELOG，看 X 是否记了改动
2. 检查改动是否影响 02 状态（更新 02 的对应行）
3. 检查改动是否破坏 06 铁律（grep 关键字验证）
4. 检查是否引入跨文件依赖（`grep -r <新符号>` 看是否被其他地方用到）
5. 输出"通过 / 有问题（具体问题）"二选一

### 3.3 冲突检测（轻量）

```bash
# 任务完成后跑一遍，看是否有"两 AI 都改同一文件"
git diff --name-only HEAD~5 HEAD | sort | uniq -c | sort -rn | head -10
```

如果同一文件被多个 agent 改过 → 看 diff 是否冲突，让写代码那一方复检。

## 4. 任务卡模板

每个子任务发到对应 agent 时，**必须带**这套前缀（用户复制粘贴即可）：

```markdown
# 任务卡：<任务名>

## 必读
1. `docs/06-AI工作手册.md`（铁律 + 误判清单 + 自检清单）
2. `docs/03-规划与进行中.md` 找你的任务对应行
3. 本次任务相关的历史踩坑：`docs/04` 中搜索关键词

## 任务描述
<一段话，清楚说明要做什么、做完什么样>

## 涉及文件
- `E:\AI小说创作\backend\app\xxx.py`（要改）
- `E:\AI小说创作\frontend\src\xxx.vue`（要改）
- 不要碰的：`docs/_archive/`、`.workbuddy/memory/_archive/`

## 约束（来自 06 铁律）
- [ ] 不许打印用户正文/请求体（铁律 2.2.3）
- [ ] 流式代码内不许访问请求级 DB session（铁律 2.2.1，铁律 #1）
- [ ] …<按本次任务勾选>

## 验收标准
- 测过哪些接口：curl http://127.0.0.1:8000/...
- 哪些文件被改：列出
- 是否触发其它模块：列出（用 grep 确认）

## 交付物
- 代码改动
- 改完后回填 `02-已实现清单.md` 对应行（含验证方式 + 日期）
- 加一行 `CHANGELOG.md`

## 不要做
- 不要读 docs/_archive/
- 不要碰本次任务外的文件
- 不要"顺便优化"其它模块
```

## 5. 调度约定

### 5.1 任务卡命名

```
.workbuddy/tasks/2026-09-09-伏笔回注.md
.workbuddy/tasks/2026-09-09-前端树状优化.md
```

### 5.2 进度看板（人肉维护）

每个任务卡底部加一个状态区，调度 WB 验收后改状态：

```
## 状态
- [ ] 已生成任务卡
- [ ] 已发给 <agent>
- [ ] <agent> 报告完成
- [ ] 调度 WB 验收通过
```

### 5.3 中断恢复

如果切上下文后忘了任务进度：
- 看 `docs/06` §1 文档索引 + `CHANGELOG` 最近 10 行 = 当前状态
- 看 `.workbuddy/tasks/` 目录下任务卡 = 待办 / 进行中 / 已完成

## 6. 何时该升级到真正调度系统

只有以下条件**同时满足**才考虑：

- [ ] 你开始**并发**调度多个 AI（不等 A 完成就发 C）
- [ ] 多个 AI 频繁改**同一文件**
- [ ] 任务卡数量 > 10/周，靠人肉记不住

到那时再考虑写一个简易调度器（消息队列 + 状态机）。现在不需要。

## 7. 何时**不要**让多个 AI 碰同一任务

| 场景 | 谁来 |
|---|---|
| 改 prompt / SKILL 内容 | WB 写码（GLM-5.3-flash），其它 agent 不碰 |
| 改后端流式逻辑 | WB 写码 |
| 改前端组件 | TRAE 或 WB 写码，二选一 |
| 写测试用例 | TRAE / OpenCode |
| 跑数据迁移 / 清理 | WB 写码（验证能力要求高） |
| 写文档 / 改 README | OpenCode（轻量活） |
| 排查跨模块 bug | Zcode（周末）或 WB 写码 |
