**4.2 观测消费端 —— token 计量 + trace_id 可查**

此前 `trace_id` 只出现在响应信封里、**从不落库**；token 用量完全没提取 —— 成本治理为零。

- **适配器提取 usage**（**零签名侵入**：用 `adapter.last_usage` 属性传出，因为流式接口是生成器、无法 return）：
  OpenAI `prompt_tokens/completion_tokens`；Claude `input_tokens/output_tokens`（**分散在 `message_start`
  与 `message_delta` 两个事件里，必须累积**，只取一处会丢一半）；Ollama `prompt_eval_count/eval_count`（**只在 done 帧**）。

- **如实区分「真实」与「估算」**：多数厂商**流式不回 usage** → 按字符估算并标 `estimated=True`，
  页面单独提示"其中 N 次为估算"。**且取不到时返回 None、不硬造 0** —— 否则"没数据"会伪装成"零消耗"。

- **`trace_id` 贯通**：生成时生成一个，写进 **用量记录 + 日志 + `done` 事件** ——
  使「前端看到的那次生成」↔「后台日志」↔「用量明细」三者能互相对上。
