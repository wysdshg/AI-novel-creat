# 全局库注入指南（设定库 / 资料库 / 写作 SKILL 库）

> 适用范围：把内容上架到「全局共享库」，让 AI 在对话与章节生成中按规则自动注入。
> 对应后端三大全局模块：`settings`（设定库）、`reference_docs`（资料库，以 `GLOBAL_PROJECT_ID` 隔离）、`custom_skills`（写作 SKILL 库）。
> 基础 URL（本地开发）：`http://localhost:8000/api/v1`，所有路径不带尾部斜杠。
> 统一响应信封：`{"code":0,"message":"success","data":{...},"trace_id":"..."}`，`code==0` 即成功。

---

## 0. 三大全局库一览

| 维度 | 全局设定库 | 全局资料库 | 全局写作 SKILL 库 |
| --- | --- | --- | --- |
| 存什么 | 结构化设定（境界/货币/体系/规则），**等级阶梯 + 短描述** | 长文本素材（大纲/背景/考据/词表），**按需加载正文** | AI 提示词模板（按场景注入的「技能/约束」） |
| 数据表 | `settings`（无 project_id，天然全局） | `reference_docs`（与小说共用，**以 `project_id="__global__"` 隔离**） | `custom_skills`（无 project_id，天然全局） |
| 写入端点 | `POST /settings` | `POST /references/global` | `POST /global-skills` |
| 最常用字段 | name / category / levels / description / tags / is_template | filename / content_text | name / prompt_body / trigger / enabled / tags |
| 注入到「对话」 | 全量注入（体系类排前） | 目录 + `LOAD_REFS` 协议按需取正文 | trigger∈{discussion, all} 且 enabled 时注入 |
| 注入到「章节」 | layer_world（可 setting_ids 过滤） | pick_relevant top-4 + 全局池 top-up | trigger∈{chapter, all} 时经 skill_dispatch 注入 |
| 跨小说复用 | `is_template=true` 可在建小说时勾选 | 经 `import-global` 复制进小说 | 永远全局生效（按 trigger 分发） |

> 三者语义不同，不要混用：
> - **设定库** = 简洁的「事实/阶梯」（如九品官制、修炼境界），模型必须严以此为准。
> - **资料库** = 大段参考文本（如取名素材大全、某朝代考据长文），太占窗口，故按需加载。
> - **SKILL 库** = 给 AI 的「行为指令/风格约束」（如「古风用词」「反 AI 味」），不是知识而是规则。

## 1. 全局设定库（settings）

### 1.1 字段 Schema（POST 入参 = `SettingCreate`）

```json
{
  "name": "宋代科举·考试层级",          // 必填，≤120 字
  "category": "体系",                    // 境界 / 货币 / 体系 / 规则 / 其它（默认「其它」）
  "levels": ["县试","发解试","省试","殿试"], // JSON 数组，等级/条目阶梯；注入时永远展示
  "description": "四级考试：1.县试……",   // 可选详细说明；仅相关时展开（见 §1.3）
  "tags": ["科举","宋代","县试"],          // 检索关键词
  "is_template": true                    // 是否可被新建小说时挑选（建小说勾选用）
}
```

### 1.2 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/settings` | 列表（`?category=&keyword=&template_only=`） |
| POST | `/settings` | 新建（本文重点） |
| GET | `/settings/{id}` | 详情 |
| PUT | `/settings/{id}` | 修改（全字段可空，空值=不改） |
| DELETE | `/settings/{id}` | 删除 |

### 1.3 怎么被注入（关键点）

- **全局对话（未选小说）**：`_build_global_system` 始终**全量**注入所有设定，按分类排序（「体系」排最前，确保小模型注意力先落在官制/知识类设定上），并附 `⚠️ 以上数据为权威资料，必须以此为准`。
- **小说级对话 / 章节**：`layer_world` 注入。若小说设了 `setting_ids`（非空），**只注入选中的设定**；`setting_ids=null`=全量，`[]`=不注入。
- **省 token 模式（relevant）**：开启 `NA_CHAPTER_LAYER_MODE=relevant` 后，`name + levels` **永远保留**（模型始终知道有哪些体系，不回归人设），仅 `description` 按相关性展开；`境界/修炼` 类为「骨干」，其 description 始终展开。

> 设计经验：**阶梯（levels）放永远展示的简短结构**，**冗长说明放 description**。一条设定过长就拆成多条（如把科举拆成「考试层级」「授官品秩」两条），既直观又不撑爆 prompt。

### 1.4 写入示例（curl）

```bash
curl -X POST "http://localhost:8000/api/v1/settings" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "宋代科举·考试层级",
    "category": "体系",
    "levels": ["县试","发解试（州府试）","省试（礼部试）","殿试（御试）"],
    "description": "四级考试：1.县试——各县每年举行，合格称\"童生\"，获发解试资格。2.发解试——各州府每三年举行，合格称\"举人\"，第一名解元。3.省试——礼部在京城主持，合格即进士及第，第一名省元。4.殿试——皇帝亲策，分三甲：一甲进士及第（状元/榜眼/探花），二甲进士出身，三甲同进士出身。",
    "tags": ["科举","宋代","县试","举人"],
    "is_template": true
  }'
```

返回 `data.id` 即设定 ID，可用于 `PUT/DELETE` 或填进小说的 `setting_ids`。

## 2. 全局资料库（references/global）

### 2.1 字段 Schema（POST 入参 = `ReferenceDocCreate`）

```json
{
  "filename": "宋代官制考据",     // 必填，≤200 字
  "content_text": "全文……",      // 文本正文，硬上限 200K 字符
  "content_type": "text/plain",  // 默认 text/plain
  "size": 12345                  // 字节，默认 0（后端一般按正文自动算，可不传）
}
```

写入后后端自动生成 `summary`（要旨）与 `tags`（关键词），并把 `source` 置为 `"global"`；列表/目录接口**不返回正文**，需走详情接口或按需加载。

### 2.2 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/references/global` | 列出全局资料（不含正文） |
| POST | `/references/global` | 上传全局资料（本文重点） |
| GET | `/references/global/{doc_id}` | 详情（含正文） |
| DELETE | `/references/global/{doc_id}` | 删除 |
| GET | `/references/global/catalog` | 全局资料「文件目录」：id / 名 / 摘要 / 标签 / token 估算 / locked（给 AI 决策用） |
| POST | `/projects/{project_id}/references/import-global` | 把选中的全局资料**复制**进某小说（`{"doc_ids":["id1","id2"]}`） |

### 2.3 怎么被注入（关键点）

- **全局对话**：`build_catalog(GLOBAL_PROJECT_ID, include_global=True)` 生成「文件目录」作为稳定前缀，并附**加载协议**——AI 判断需要某资料时，只输出一行 `LOAD_REFS:<id1>,<id2>` 然后停止，后端把对应正文注入后再让 AI 续答（无需用到的资料不占窗口）。schema 文档、取名素材等量大素材适合放这里。
- **章节生成**：默认走 `pick_relevant` 按相关性挑项目内 top-4；开启 `NA_CHAPTER_REF_MODE=hybrid` 后，额外用确定性 top-up 注入全局池中 `score>=4` 的 top-2（如取名类 hint 自动补「姓氏/男名」素材）。

> 与设定库的区别：**资料库是正文文本，按需加载**；设定库是结构化的「事实阶梯」，常驻。资料不要塞进设定库（会撑爆 prompt），设定不要写成资料长文。

### 2.4 写入示例（curl）

```bash
curl -X POST "http://localhost:8000/api/v1/references/global" \
  -H "Content-Type: application/json" \
  -d '{
    "filename": "宋代科举与官制考据",
    "content_text": "宋代科举分四级……（此处放大段考据正文，可分多条资料上传）",
    "content_type": "text/plain"
  }'
```

把资料复制进某小说（建小说时若想直接带进去）：

```bash
curl -X POST "http://localhost:8000/api/v1/projects/{project_id}/references/import-global" \
  -H "Content-Type: application/json" \
  -d '{"doc_ids":["<全局资料id1>","<全局资料id2>"]}'
```

## 3. 全局写作 SKILL 库（custom_skills / /global-skills）

### 3.1 字段 Schema（POST 入参 = `CustomSkillCreate`）

```json
{
  "name": "古风用词器",                      // 必填，≤80 字
  "description": "生成时优先用四字成语替代口语", // 可选说明
  "prompt_body": "写作时……（注入 AI 的提示词正文）", // 实际注入内容，可空（空则不注入）
  "trigger": "all",                         // discussion / chapter / memory / parse / all（默认 all）
  "enabled": true,                          // 默认 true
  "tags": ["古风"]
}
```

> **注意**：此 SKILL 与「角色技能」（`/projects/{id}/skills`，按小说隔离、与角色绑定）**完全不同**——本库是给 AI 的提示词模板，跨小说共享。

### 3.2 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/global-skills` | 列表（`?trigger=&enabled_only=&keyword=`） |
| POST | `/global-skills` | 新建（本文重点） |
| GET | `/global-skills/{id}` | 详情 |
| PUT | `/global-skills/{id}` | 修改 |
| DELETE | `/global-skills/{id}` | 删除 |

### 3.3 怎么被注入（关键点）

- **trigger 决定注入阶段**：
  - `discussion` → 对话/商讨场景（`_collect_skill_blocks` 过滤 `trigger∈{discussion,all}` 且 `enabled=true` 且 `prompt_body` 非空，按 name 字典序拼接，注入「【写作技能合集】」段）。
  - `chapter` → 章节生成场景（`builder.py` 调 `skill_dispatch.build_block(db,"chapter")`）。
  - `memory` / `parse` → 记忆压缩 / 设定解析场景（同样经 `skill_dispatch` 按对应 trigger 分发）。
  - `all` → 所有阶段都注入。
- 多个 SKILL 命中同一 trigger 时，按 `name` 字典序拼接（避免顺序漂移导致前缀缓存失效）。
- 只有 `enabled=true` 且 `prompt_body` 非空的 SKILL 才会真正注入。

### 3.4 写入示例（curl）

```bash
curl -X POST "http://localhost:8000/api/v1/global-skills" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "古风用词器",
    "description": "生成时优先用四字成语替代口语",
    "prompt_body": "在生成正文时，优先使用四字成语、文言虚词替代现代口语；对话可适度白话，但叙述与描写须保持古风质感。",
    "trigger": "all",
    "enabled": true,
    "tags": ["古风","文风"]
  }'
```

## 4. 综合实战：上架一套「宋代科举」知识包

目标：让 AI 在未选小说时也能准确回答宋代科举/官制问题，并在写古风小说时自动套用风格。

**① 设定库（结构化事实，常驻）**— 用 §1.4 的 curl 写两条：

- `宋代科举·考试层级`（category=体系，levels=县试→发解试→省试→殿试）
- `宋代科举·及第授官品秩`（category=体系，levels=举人→一甲→二甲→三甲，description 写「考上即任几品官」）

**② 资料库（长考据，按需）**— 用 §2.4 的 curl 写一份 `宋代科举与官制考据`（大段正文）；全局对话时 AI 仅在需要时 `LOAD_REFS` 拉取。

**③ SKILL 库（风格约束）**— 用 §3.4 的 curl 写一个 `古风用词器`（trigger=all），让 AI 写作自动走古风。

最终效果：

- 未选小说 → 全局对话：设定全量注入（体系排前）+ 古风 SKILL 常驻 + 考据资料目录按需加载。问「县尉几品」直接命中设定库作答。
- 选了某小说 → 若小说 `setting_ids` 勾选了上述两条设定，则只注入这两条；章节生成时古风 SKILL（trigger=chapter）自动生效。

## 5. 常见坑与注意

1. **端口**：后端默认 `8000`；若宿主后端换了端口，curl 要改对应端口。
2. **改后端代码须手动重启**：改了 `routers/services` 后，宿主侧用 `E:\AI小说创作\.venv\Scripts\python.exe backend/dev.py` 重启才生效（Uvicorn reload 对 `E:\` 共享盘不生效）。
3. **设定库不要塞长文**：长说明放 `description` 且靠 relevant 模式按需展开；超长考据请放资料库。
4. **SKILL 的 prompt_body 必须非空**才会注入；`enabled=false` 会被跳过。
5. **全局 vs 小说级隔离**：
   - 设定库：全局全量，小说可用 `setting_ids` 收窄。
   - 资料库：全局池与小说各自独立；要带进小说用 `import-global` 复制（不是引用）。
   - SKILL 库：永远全局按 trigger 生效，无小说级隔离。
6. **token 优化开关**（体验按需注入才生效，且须在**同一启动后端的终端**设环境变量再重启）：
   - 设定/角色层按需：`NA_CHAPTER_LAYER_MODE=relevant`
   - 章节参考文档 hybrid：`NA_CHAPTER_REF_MODE=hybrid`
