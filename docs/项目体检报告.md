# 项目体检报告

- 日期：2026-08-13
- 范围：后端（FastAPI/SQLAlchemy/Pydantic v2）、前端（Vue3/Element Plus/Pinia）、脚本与文档一致性
- 方式：全量代码扫描 + 关键点实测验证，**只诊断，未修改任何代码**
- 结论总览：无致命崩溃级问题，但存在 **2 个高风险数据丢失/接口全挂**、若干中风险逻辑 bug、一批废弃脚本残留（含一处明文密钥）。

---

## 一、高风险（建议优先处理）

### 1.1 工作流更新后接口全 500（数据已污染）— 后端
- `app/services/workflow_crud.py:94-105`：更新流程 `model_dump(exclude_unset=True)` 未传 `by_alias=True`。
  - `FlowEdge.from_` 字段会以 `from_` 键名入库，而非 alias `from`；后续 `Workflow.model_validate` 因 alias 缺失抛 `ValidationError`。
  - 影响：对含边的流程做 PUT 更新后，GET/PUT 全 500；错误数据已持久化。
  - 修复方向：dump 时补 `by_alias=True`；建议顺带校验旧库中的脏数据。

### 1.2 重新生成章节覆盖真实正文（静默丢失）— 后端
- `app/routers/chapter.py:486-489, 519-526`：`use_model=False` 且对已有 `chapter_id` 重新生成时，占位文本直接覆盖真实章节正文，无备份、无确认。
  - 影响：用户以为只是"重新生成预览"，实际历史正文被覆盖。

## 二、中风险（逻辑 bug / 数据一致性）

### 2.1 删除作品不清理子表 → 孤儿行 — 后端
- `app/services/project_crud.py:83-96`：`delete_project` 的级联清单缺 `VolumeORM / ArticleORM / ReferenceDocORM / LocationORM / ChapterMemoryORM / StageSummaryORM / DiscussionLoadLogORM`。
  - 影响：删小说后子数据残留，重新建同名作品会出现"幽灵结构"。

### 2.2 删卷/删篇不级联 → 孤儿章节仍被列出 — 后端
- `app/services/article_crud.py:67-73`：删篇不删其下章节。
- `app/services/volume_crud.py:53-59`：删卷不删其下篇/章。
  - 影响：前端侧栏仍能列出已删卷/篇下的章节。

### 2.3 伏笔注入重复 — 后端
- `app/core/context/layers.py:466-477`：`layer_foreshadows` 的 relevant 分支把 pending 循环写了两次。
  - 影响：同一伏笔被注入两次，占用上下文预算、模型易重复。

### 2.4 篇章参考目录永不命中 — 后端
- `app/routers/discussion.py:405`：把 `chapter_id` 当 `article_id` 传给 `build_catalog`。
  - 影响：章级对话的"参考文档/设定"目录查不到任何条目，`LOAD_REFS` 相关能力在章线程失效。

### 2.5 模型切换即报错 — 前端
- `views/ChatView.vue:48`、`components/workspace/ChatInput.vue:53` 绑定 `store.selectModel`，但 `store/project.js` 的 actions 中**不存在该方法**（仅 `loadModels`/`currentModelId` 状态，无 `selectModel` action）。已实测确认。
  - 影响：每次切换模型抛 `TypeError`，模型不生效（实际仍是 currentModelId 逻辑）。

### 2.6 实体确认永远显示"已写入 0 条" — 前端
- `views/ChatView.vue:188`：双重解包 `res?.data?.data`；而 `api/http.js` 拦截器已解包过一次 → 取到的是 `data` 字段本身，实体统计始终为 0。
  - 影响：写入成功但 UI 误导用户"没写入"。

### 2.7 生成章节的 ingest 进度卡死 — 前端
- `components/workspace/GenerateChapterDialog.vue:421-434`：监听 `ingest` 事件，但后端 `chapter.py` 只发 `ingest_start` / `ingest_done`。
  - 影响：ingestState 永远停在中间态，对话框卡住。

### 2.8 删除小说后状态残留 — 前端
- `store/project.js:184-192` `deleteNovel`：未重置 `currentConversationId`、未清空 `discussionMessages`。
  - 影响：删除后界面仍显示已删小说的旧对话。

### 2.9 多个"漫游对话"互相串台 — 前端
- `store/project.js:354-358`：多个全局漫游对话共用后端 `__global__` 线程（`conversationId=null`）。
  - 影响：不同对话窗口消息互相污染。

### 2.10 删除对话提示与行为矛盾 — 前端
- `layout/MainLayout.vue:426-436` 提示"仅从列表移除"，但 `store/project.js:459-464` 的 `discussionClear` 实际调用后端删除消息。
  - 影响：用户以为只是隐藏，实际数据被删，易误操作。

### 2.11 聊天面板无自动滚动 — 前端
- `components/workspace/ChatPanel.vue`：无 `scrollTop` 追踪。
  - 影响：流式长回复不可见，需手动滚动。
