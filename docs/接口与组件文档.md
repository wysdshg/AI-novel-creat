## 3. 模块逐项说明

### 3.1 设定库（全局，路径 `/api/v1/settings`）

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/settings` | GET | 列表（`?category=&keyword=&template_only=`） |
| `/settings` | POST | 新建（name 必填） |
| `/settings/{id}` | GET | 详情 |
| `/settings/{id}` | PUT | 修改（全字段可空，仅非空字段生效） |
| `/settings/{id}` | DELETE | 删除 |

**Schema（参考）**：
```json
{
  "id": "…", "name": "玄幻九境界", "category": "境界",
  "levels": ["炼气","筑基","金丹",...],   // JSON 数组
  "description": "...", "tags": ["玄幻","高武"], "is_template": true,
  "created_at": "...", "updated_at": "..."
}
```

**前端组件**：`SettingView.vue`，组件作用「列出 / 搜索 / 编辑全局设定项，标记可被创建小说挑选的模板」。
完成情况：✅ CRUD + 筛选 + 模板标注 + 多行/标签表单解析均可用。

### 3.2 写作 SKILL（全局，路径 `/api/v1/global-skills`）

> ⚠️ 与资料库 `Skill` 不同：本模块是 AI 提示词模板（拼入 prompt），无 project_id 隔离。

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/global-skills` | GET | 列表（`?trigger=&enabled_only=&keyword=`） |
| `/global-skills` | POST | 新建 |
| `/global-skills/{id}` | GET / PUT / DELETE | 详情/改/删 |

**Schema（参考）**：
```json
{
  "id": "...", "name": "古风用词器",
  "description": "...", "prompt_body": "...",
  "trigger": "chapter",        // discussion|chapter|memory|parse|all
  "enabled": true, "tags": ["古风"],
  "created_at": "...", "updated_at": "..."
}
```

**前端组件**：`CustomSkillView.vue`。
完成情况：✅ CRUD + 启停开关 + trigger 选择 + keyword 搜索均可用。

### 3.3 工作流（全局，路径 `/api/v1/workflows`）

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/workflows` | GET | 列表（`?active_only=&keyword=`） |
| `/workflows` | POST | 新建（节点/边 JSON 自动校验 DAG 端点） |
| `/workflows/{id}` | GET / PUT / DELETE | 详情/改/删 |
| `/workflows/{id}/duplicate` | POST | 复制（id 重生，name 加「(副本)」） |

**Schema（参考）**：
```json
{
  "id": "...", "name": "开篇套路",

    {"id":"start","type":"start","label":"开篇"},
    {"id":"hook","type":"step","label":"钩子"}

  "edges": [{"from":"start","to":"hook","condition":"always"}],
  "tags": ["开篇"], "is_active": true
}
```

**前端组件**：`WorkflowView.vue`。
完成情况：✅ CRUD + 启停 + 复制 + JSON 实时校验（节点 id 唯一 / 边端点存在）+ 节点/边数量显示均可用。可视化拖拽后续接 vue-flow / svg-flow。
可扩展点：本轮只 CRUD + 静态 JSON，未来：

## 4. 顶部 nav 系统（前端的「可扩展性」展示）

为支持「后续加 tab 不再改 MainLayout」的设计目标，nav 改造遵循：

- 一级 tab（`meta.tab = 'parent'`）：出现在 MainLayout 顶部
- 二级 tab（`meta.tab = 'sub'` 且 `meta.tabParent = 'X'`）：当一级 tab 激活为「X」时，显示在数据库 subtab row
- `hideTab: true`：路由可达，但不出现在任何 tab（侧栏树 / 深链可访问）

**新增一个一级 tab 的步骤**：

1. 后端：建 `xxx.py / xxx_crud.py / schemas/xxx.py`，在 `main.py` 注册 router（参照本文 §1.1）
2. 前端：写 `api/xxx.js` + `views/XxxView.vue`，在 `router/index.js` 加一条 `meta.tab='parent'` 路由
3. MainLayout **零改动**——tabs 自动渲染

**新增一个数据库子 tab 的步骤**：

1. 后端：同上，路径挂 `/projects/{id}/xxx`
2. 前端：写 view + api，在 `router/index.js` 加 `meta.tab='sub', tabParent='database'` 路由
3. MainLayout **零改动**——subtab row 自动渲染
